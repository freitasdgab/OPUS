4. MELHORIAS TECNICAS (ARQUITETURA, DIAGRAMAS E BANCO DE DADOS)
================================================================================

1. CASOS DE USO (Figura 4):
   - Cuidados com as setas `<<include>>` e `<<extend>>`:
     * O `<<include>>` aponta do Caso de Uso base para o Caso de Uso incluido 
       (ex.: "Realizar Licao" aponta para "Executar Codigo").
     * O `<<extend>>` aponta do Caso de Uso extensor (o que e opcional/condicional) 
       para o Caso de Uso base (ex.: "Usar Dica" aponta para "Realizar Licao").
     * Os Atores (Aluno/Administrador) NUNCA devem se ligar diretamente a Casos 
       de Uso que sao apenas `<<extend>>` ou `<<include>>`. O ator se liga ao caso 
       de uso principal. Na Figura 4, garanta que os atores estejam conectados 
       somente aos casos de uso primarios.

2. QUALIDADE DO APENDICE (ROTEIRO DE VERIFICACAO FUNCIONAL - Tabela 4):
   - Onde consta apenas "Funcionou", melhore a descricao tecnica para demonstrar 
     rigor metodologico. 
   - Exemplos de substituicao:
     * De: "Funcionou."
     * Para: "Validado com sucesso: formulario bloqueia duplicidade exibindo aviso 
       de e-mail ja cadastrado; novos registros sao inseridos no MySQL com senha 
       criptografada via password_hash()."
     * De: "Funcionou: o sistema avisa quando a resposta esta correta..."
     * Para: "Validado com sucesso: ao selecionar alternativa correta, exibe banner 
       verde e pontua XP; em caso de erro, desconta 1 vida e exibe gabarito em banner 
       vermelho."
     * De: "Funcionou." (no item do Wandbox)
     * Para: "Validado com sucesso: codigo Java compilado via API externa e retorno 
       de stdout impresso no terminal em tempo medio de 1,8 segundos."

3. COMPLIANCE COM A LGPD (Secao 3.5.1):
   - Voce citou muito bem a Lei no 13.709/2018 (artigos 6o e 46).
   - Sugestao para enriquecer: mencione que a plataforma armazena apenas os dados 
     estritamente necessarios para a finalidade pedagogica (principio da necessidade / 
     minimizacao dos dados), como nome e e-mail, e que senhas sao protegidas por 
     hash unidirecional (BCrypt), alem de permitir que o usuario exclua ou altere seus 
     dados cadastrais no perfil.

GLOSSARIO

AJAX: Tecnica de desenvolvimento web que permite a atualizacao assincrona de 
dados da pagina sem a necessidade de recarrega-la por completo.

API (Application Programming Interface): Conjunto de rotinas, protocolos e 
padroes de comunicacao que permite a integracao entre softwares distintos.

Back-end: Camada da aplicacao executada no servidor, responsavel pelo 
processamento das regras de negocio, controle de acesso e consultas ao banco de 
dados. No OPUS, foi desenvolvido em PHP.

Bau de Recompensa: Elemento ludico concedido ao estudante apos completar tres 
licoes em uma unidade, premiando-o com XP adicional ou vidas.

DER (Diagrama Entidade-Relacionamento): Modelo grafico que descreve as 
entidades, atributos e associacoes logicas de uma base de dados relacional.

Divisao: No modulo de ligas, corresponde a categoria competitiva (Bronze, 
Prata, Ouro, Diamante e Mestre); na trilha didatica, agrupa conjuntos de 
unidades sob um mesmo topico tematico.

Endpoint: Ponto de extremidade ou URL especifica de uma API por onde sao 
recebidas requisicoes e emitidas respostas em formatos como JSON.

Front-end: Camada da aplicacao executada diretamente no navegador web do 
cliente, compreendendo elementos visuais e de interatividade (HTML, CSS e JavaScript).

Gamificacao: Aplicacao de elementos tipicos de jogos (pontos, recompensas, 
niveis, classificacoes e penalidades) em contextos nao ludicos, como na educacao.

JVM (Java Virtual Machine): Maquina virtual responsavel por interpretar e 
executar o bytecode compilado de programas Java em diferentes plataformas.

LGPD (Lei Geral de Protecao de Dados Pessoais): Legislacao brasileira (Lei no 
13.709/2018) que regulamenta o tratamento de dados pessoais por pessoas fisicas 
ou juridicas.

Liga: Agrupamento semanal de ate 30 alunos que competem entre si com base no XP 
obtido durante o ciclo de sete dias.

LLM (Large Language Model): Modelo de linguagem neural treinado em bases 
massivas de texto, empregado para gerar dialogos contextuais, como na Opi IA.

OAuth 2.0: Framework de autorizacao que viabiliza o compartilhamento seguro de 
dados e login federado sem a transferencia direta de senhas (ex.: Login com Google).

Ofensiva (Streak): Metrica de engajamento que contabiliza o numero de dias 
consecutivos em que o usuario executou ao menos uma atividade na plataforma.

Opi IA: Assistente virtual pedagogica integrada ao OPUS para sanar duvidas de 
Java e orientar o estudante na navegacao.

Token: Sequencia criptografica temporaria utilizada para comprovar a 
autenticidade de sessoes ou requisições entre aplicacoes clientes e servidores.

Trofeu: Conquista comemorativa desbloqueada por metas especiais, classificada 
por niveis de raridade (comum, raro, epico e lendario) e exibida no perfil.

Unidade: Modulo de aprendizagem tematico composto por licoes teorico-praticas e 
um projeto de programacao.

Wandbox: Servico remoto de compilacao e execucao de codigo-fonte multiplataforma, 
acessivel por API, adotado pelo OPUS para compilar codigos Java sem exigir JDK local.

XP (Experience Points): Unidade de pontuacao adquirida pelo aluno ao acertar 
exercicios e concluir desafios na plataforma.
